# Contextarium redesign technical feasibility assessment

**Assessment date** November 27, 2026  
**Repository** [ericslandry/contextarium](https://github.com/ericslandry/contextarium)  
**Audience** Architecture reasoning agent reviewing feasibility against the agreed product vision  
**Evaluation baseline** [REDESIGN.md](https://github.com/ericslandry/contextarium/blob/main/docs/REDESIGN.md) and [REDESIGN-FEASIBILITY.md](https://github.com/ericslandry/contextarium/blob/main/docs/REDESIGN-FEASIBILITY.md), including its [section 6 validation protocol](https://github.com/ericslandry/contextarium/blob/main/docs/REDESIGN-FEASIBILITY.md#6-targeted-handoff-work-validation-protocol)

This assessment uses the completed experiments and research. It summarizes results in place so the reader can evaluate the conclusions without access to the local execution environment. The [prior validation record at commit 7d5435a](https://github.com/ericslandry/contextarium/blob/7d5435a4d5d5c78cf4bc2a7bd234f184fcb869c0/docs/REDESIGN-VALIDATION.md) preserves the detailed measurements and provenance.

## 1. Executive assessment

**The agreed product vision is technically achievable in principle. Proceed with clean architecture design and a bounded prototype. Keep automated live composition and general generated rich content behind validation gates.** The target is a transient, agent-curated spatial workspace alongside an ongoing Copilot conversation. The agent composes independently addressable HTML, CSS, SVG and simple native elements. The human navigates and retains camera authority. Contextarium owns the authoritative workspace and controls publication.

| Evidence classification | Architectural conclusion |
| --- | --- |
| **Validated** | In one real Copilot desktop session, a native Dynamic Workflow ran a model concurrently with a foreground request. In a separate model-free native run, a workflow result updated the visible Canvas. Native Canvas displayed representative rich content in opaque frames. Deterministic tests demonstrated single-writer publication, stale-work rejection, reconnect, import and camera fencing. |
| **Invalidated for the tested configuration** | The workflow-local agent validator rejects the shared type's `skills` field and requires explicit `infer: false`. A separately spawned isolated SDK runtime did not inherit usable authentication from the signed-in desktop. The disposable local marketplace's per-plugin Update and Uninstall actions failed despite an Installed entry. Local source refresh, marketplace removal and prior private GitHub marketplace upgrades are distinct paths. |
| **Uncertain** | Effective worker tool restrictions under foreground grants, reliable event attribution and context replay, a model result passing through the complete validation-to-Canvas path, production markup containment, smooth native multiscale navigation, and skill access in a background worker. Account portability, sustained latency and cost, and host retention are also open. |

There are two material adoption blockers. **Background automation needs enforceable composition-only access and reliable isolation of foreground events from worker events.** **Agent-generated rich content needs a tested containment policy and an interaction budget that preserves the spatial experience.** The current data exposes these blockers without ruling out the vision. The isolated SDK fallback has an additional authentication blocker in the tested setup.

**Evidence terms.** *Live Copilot* means an actual desktop-host observation. It is marked *model-free* where no model ran. *Deterministic* means a controlled fixture or simulated foreground activity. *Documentation* means claims from the retained vendor documentation or installed declarations. *Inference* means an architectural conclusion drawn from those results.

## 3. Critical architectural findings

### Copilot integration, execution and usage

The tested native entry point imported `createCanvas`, `defineWorkflow` and `joinSession` from `@github/copilot-sdk/extension`. The live foreground calls used `session.sendAndWait({prompt, mode: "enqueue"}, timeoutMs)` as a test driver for the ordinary conversation. The worker used the workflow path. The workflow created a separate activity entry and returned a structured value, with no additional foreground chat message attributed to the worker. Native workflow registration and running are real on the tested versions. Treat the preview API as a version-sensitive adapter boundary.

~~~js
const session = await joinSession({
  canvases: { definitions: [canvas] },
  workflows: [workflow],
});

const unsubscribe = session.on(listener);
const run = await session.workflow.start(workflow, options);
const status = await session.workflow.getRun(run.runId);
const result = await session.workflow.waitForRun(run.runId, { signal });
// Cancellation was exercised on separate deterministic runs.
await session.workflow.cancel(otherRunId);
unsubscribe();
~~~

Inside `defineWorkflow({meta, agents, run})`, the deterministic probe used `ctx.step(label, callback)` and `ctx.signal`. The model-backed run used `ctx.agent(prompt, {agent: ctx.agents.spatial, schema, timeoutSeconds})`. The workflow-local definition accepted `infer: false` and `tools: []`. The observed listener recorded zero tool starts, but the effective tool catalog was never enumerated and no denial was exercised. GitHub's documented session-grant inheritance remains relevant to the threat model. The run tested a controlled, session-local composition job on an available model. It did not establish that an arbitrary signed-in account, plan or organization policy will provide an equivalent model and permission set. [Recorded APIs and preflight](https://github.com/ericslandry/contextarium/blob/7d5435a4d5d5c78cf4bc2a7bd234f184fcb869c0/docs/REDESIGN-VALIDATION.md#native-workflow-and-canvas) · [GitHub workflow permissions documentation cited in the feasibility research](https://docs.github.com/en/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/dynamic-workflows#permissions-for-dynamic-workflows)

The first desktop preflight showed **No models available** and sent no model requests. A subsequent fresh no-repository session with **Copilot Fusion · Standard** completed the authorized comparison. The separate SDK preflight used the installed runtime in isolated `empty` mode. It started and answered a status check, then `getAuthStatus()` reported unauthenticated. Model enumeration and an authenticated independent turn were not attempted. Native Fusion success establishes an available desktop path for the tested account. Authentication and effective controls for a separate runtime require their own evidence. [Preflight](https://github.com/ericslandry/contextarium/blob/7d5435a4d5d5c78cf4bc2a7bd234f184fcb869c0/docs/REDESIGN-VALIDATION.md#approved-live-model-preflight)

### Rich rendering, performance and accessibility

Opaque sandboxed `srcdoc` worked in both hosts. Edge also rendered an isolated HTTP document with restrictive response headers as a frame and during direct navigation. Tested script/handler signals, host access and subresource cases produced no observed fixture messages or sink hits. Direct HTTP navigation in Edge produced CSP/origin blocks with no script marker or sink hit. The native WebView did not run the HTTP-header comparison. These are results for controlled fixtures. The remaining containment tests cover in-frame navigation and refresh, forms, broader CSS/SVG reference and load paths, privileged bridges, deceptive UI and resource exhaustion. ### State authority and independent Canvas updates

The evidence supports a session-owned, in-memory single writer with three distinct checks. Session generation fences jobs across import, reset and close. Workspace revision and conversation freshness fence obsolete changes within the active session. A browser-owned camera epoch lets a coherent content update commit while rejecting its accompanying camera guidance after human takeover. The deterministic transport recovered through a full snapshot. The native result marker used a polling probe; the older shipping renderer demonstrated loopback SSE/HTTP, acknowledgements and renderer epochs with different state ownership. Reuse the transport ideas after validating their identity, origin and teardown assumptions for the redesigned direction of authority. [Prior native and deterministic results](https://github.com/ericslandry/contextarium/blob/7d5435a4d5d5c78cf4bc2a7bd234f184fcb869c0/docs/REDESIGN-VALIDATION.md#native-workflow-and-canvas) · [Existing architecture](https://github.com/ericslandry/contextarium/blob/main/docs/Contextarium-Architecture.md)

## 4. Recommended architecture

1. **Use a native Copilot adapter and one background composition coordinator.** Use Dynamic Workflows in the prototype behind a replaceable provider interface. Observe supported session events, correlate by session and turn or message identity where available, and coalesce completed foreground context and explicit visualization intent. Prefer explicit triggers for the first integrated slice. Passive navigation updates context without invoking a model. Bound jobs to minimal input, one active composition job per session, one structured candidate and observable usage. Keep the worker outside the trusted Canvas and workspace commit paths.
2. **Make the session workspace manager the commit authority.** The worker proposes a bounded scene change or no change. The coordinator validates content, document budgets, revision and freshness before a coherent commit. The renderer consumes an initial or reconnect snapshot plus bounded revisioned updates. The browser owns the camera, selection and navigation history. Use the independent camera epoch for guidance. Keep manual export/import versioned and restricted to scene data. Exclude session credentials, capabilities and conversation transcripts from exports.
3. **Use an opaque content shell.** Prototype a content-agnostic world with stable object IDs, local geometry, visibility, opacity and separate content revisions. Use sandboxed script-free frames behind trusted navigation, with structural admission rules, restrictive CSP and explicit resource budgets. Evaluate the restrictive HTTP route if it improves native isolation or delivery. Retain native text or other bounded elements and consider SVG images or snapshots for overview rendering. Preserve optional semantic anchors and reading aids where scenarios justify them. Stage expensive content and cap mounted frames. Do not enable arbitrary authored JavaScript, external resource access or a privileged frame-to-host bridge.
4. **Keep native distribution and teach the redesigned authoring contract.** Preserve the native marketplace installation pattern, package-local assets and product identity. Keep the existing plugin available until the replacement meets release criteria. Bundle a human-readable authoring skill with representative examples and viewport checks. Initially pass a compact, versioned set of equivalent composition instructions explicitly to the worker. Treat that as the prototype delivery mechanism and verify actual bundled skill access separately.

**Reuse where it fits.** Preserve camera interpolation, fitting, human takeover/veto, stable identifiers and useful background techniques after provenance review. Reuse the validation concepts of atomic updates, sampled viewport checks, reconnect epochs and the inspect/compose/validate/publish sequence. Evaluate the loopback SSE/HTTP adapter and native packaging with the new authority and content boundaries. Rebuild the content contract around free composition. The current browser-authoritative v1 scene, fixed widget catalog and scheduling conventions should not determine it. [Existing architecture](https://github.com/ericslandry/contextarium/blob/main/docs/Contextarium-Architecture.md) · [Authoring guide](https://github.com/ericslandry/contextarium/blob/main/docs/AUTHORING.md) · [Native packaging](https://github.com/ericslandry/contextarium/blob/main/docs/COPILOT-PLUGIN.md)

**Alternatives and deviations.** Keep a separately scoped SDK runtime as a fallback if native tool isolation or host behavior fails. It adds authentication, policy and lifecycle overhead. Reject the foreground queue and foreground-dependent delegation as the default background mechanism because they do not provide the proven independent execution path. Reject direct host-DOM insertion and Shadow DOM as the isolation boundary. Defer a database, cross-session history and migration support until a concrete requirement warrants them. The prototype should temporarily limit visual inputs and use explicit triggers. Native workflow activity can remain visible even with result notifications suppressed, so a fully unified assistant presentation remains a product decision. No change to the long-term product vision is required on current evidence.

## 5. Remaining decisions

| Decision | Options and trade-offs | Recommendation and decision evidence |
| --- | --- | --- |
| **Bounded worker and authentication** | Native workflow uses desktop auth and scheduling. Inherited session grants and an unverified empty tool list are material risks. A separate SDK can offer stronger explicit configuration, with additional auth and lifecycle work. | Start with supported effective-tool introspection or a harmless control-and-denial test in a disposable session. Verify the worker cannot exercise disallowed capabilities under foreground grants. Fall back to the separate runtime only if it can authenticate through an approved path and prove its scope. |
| **Event attribution, work scheduling and accounting** | Explicit invocation minimizes recursion and cost. Automatic curation needs reliable attribution, catch-up semantics and rate controls. Visible workflow activity changes the single-assistant experience. | Keep explicit invocation until supported event correlation, replay handling, cancellation, results and usage are attributable to the intended session and job. Then enable coalesced automatic curation. Decide whether the host's activity UI and retention are acceptable. |
| **Rich-content admission and rendering budget** | Opaque srcdoc is validated in native Canvas. Restrictive HTTP offers other policy controls with serving and host-compatibility costs. SVG images, snapshots and native text reduce frame cost but can lose selection, accessibility or authoring flexibility. | Prototype sandboxed srcdoc with a narrow content policy. Complete isolation and resource-limit checks, and compare offscreen-frame culling and lower-cost overviews in native Canvas. Use a freely composed architecture explanation and a contrasting text-heavy scene to set release budgets and assess usability. |
| **Integrated publication, navigation and compatibility** | A session authority supports transient state and simple recovery. Full deltas, anchors, connectors, persistent history and legacy import increase complexity. | Prove one foreground-triggered model candidate through validation to visible Canvas while the human navigates. Include stale-result rejection, reconnect and camera takeover. Keep navigation history independent of content. Decide legacy import and release compatibility explicitly once real scenes expose the need. |
| **Worker authoring guidance** | Native skill discovery is proven. Workflow-local skill preload failed. Explicit versioned instructions are viable for a prototype but could increase context size and drift from the packaged skill. | Use one canonical instruction source to derive the worker payload and bundled skill. Verify a supported background loading path and measure instruction overhead and authoring quality before relying on it. |

## 6. Readiness

**Proceed with the clean redesign at architecture and bounded-prototype scope. Perform targeted validation before committing to a production provider or a production rich-content contract.** Close the effective-permission gate first because it could change the Copilot integration. Validate event attribution and one combined model-to-Canvas slice next. Native rendering performance and content containment can be profiled independently with synthetic fixtures.

**Reconsider two specific assumptions:** automatic reuse of desktop authentication for a separate SDK process and direct workflow-local skill preloading in the installed build. The native workflow, session-owned workspace and opaque rich-content prototype remain credible. General rollout requires proven worker boundaries, representative rendering and accessibility results, and an explicit compatibility and release decision.

This assessment made no new experiments or Copilot model calls and introduced no redesign code.
